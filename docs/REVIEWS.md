### P0 — 必须先修复

#### P0.1 “小类前 100”口径错误 [已在优化版修复]

- **当前实现**: 每月按 `月销量` 重新排序后取 Top 100。
- **原始要求及源字段**: 应优先依据 `小类BSR` 的 1-100 范围分析，并按 1-5、6-10、11-20、21-50、51-100 分层。
- **影响**: 整体、PP、高客单三套 Top100 及分层趋势均可能改变。
- **改造**: 建立可审计的 `小类BSR` 解析规则；多值/换行 BSR 单独标记；输出按 BSR 与按销量排名两个视角，主报告以 BSR 口径为准。

#### P0.2 2023 年度 YoY 使用不可比周期 [已在优化版修复]

- **当前实现**: 2023 完整 12 个月对比 2022 年 6-12 月共 7 个月。
- **影响**: 报告中的 2023 整体 +246.3%、PP +209.0%、高客单 +273.0%、GENIMO +823.3% 不是同周期同比。
- **改造**: 年度 YoY 仅比较完整自然年；2023 改为 2023.06-12 对比 2022.06-12 的同期同比，并明确标注 YTD/同周期。

#### P0.3 2026.03-2026.07 数据口径异常未闭环

- **现状**: 报告直接排除 5 张可见月份表；2026.04 起销量从 29.1 万跳到 292.5 万并维持百万级。
- **核验**: 异常来自源 Excel，不是导入错位。
- **改造**: 生成原始口径、可比口径和异常诊断表；在无法确认卖家精灵口径前，不将异常月份用于长期结论，但必须披露并附原值。

#### P0.4 分析过程不可复现 [已在优化版修复]

- **现状**: 缺少指标计算、报告生成和可复跑的全量审计脚本。
- **改造**: 增加统一分析程序，从 SQLite 生成结构化中间结果、Markdown 和独立 HTML；所有报告数字由代码生成，禁止手工硬编码核心指标。

### P1 — 高优先级修复

#### P1.1 高客单筛选口径不一致 [已在优化版统一NULL语义]

- **报告文字**: `标题 NOT LIKE plastic AND (标题 LIKE polypropylene OR 价格 >= 40)`。
- **实际差异**: 空标题且价格 >= 40 的 51 条记录被统计逻辑纳入，但展示 SQL 会因 NULL 三值逻辑排除；报告写 29,391 条，按展示 SQL 回算为 29,340 条。
- **改造**: 使用 `COALESCE(商品标题, '')` 固化 NULL 语义；将“材质命中”和“仅价格命中”拆分统计；补充 sandwich、woven、polypropylene 等可配置关键词表。

#### P1.2 均价定义不透明 [已在优化版提供双口径]

- **现状**: 月度均价为 SKU 标价简单平均；年度均价近似月均价再平均，不是 `销售额/销量`。
- **改造**: 同时输出 `SKU平均标价` 与 `销量加权成交均价=销售额/销量`；报告标题和公式必须明确。

#### P1.3 最终 HTML 信息不完整 [已在优化版修复]

- **现状**: Markdown 有完整月表，HTML 只展示代表月份和概括结论。
- **改造**: HTML 内提供完整月度 MoM/YoY、年度同周期同比、Top100分层表和口径说明；摘要与明细可折叠，但不能缺失。

## 复核发现 (2026-08-27) — Round 3: 工作表范围与转换可复验性

### 口径 #1: 55 张不是 Excel 界面可见子表数 [已更正文档]

- **工作簿内部**: 55 张工作表。
- **Excel 界面可见**: 23 张（4 TOP + 2025.01 至 2026.07 共 19 张月度表）。
- **隐藏**: 32 张，其中 31 张是 2022.06 至 2024.12 的有效历史月度表，1 张 `Sheet6` 无有效区域。
- **有效导入**: 54 张业务表（50 月度 + 4 TOP）。
- **分析决策**: 原始 TXT 要求分析“历年”并计算年度/月度 YoY、MoM，故保留 31 张隐藏历史表；隐藏状态不等于无效数据。

### Bug #5: `IMPORT_OVERWRITE=false` 不能防止覆盖 [待修复]

- **现象**: 配置为 false 时只是不删除 DB 文件；随后仍会删除并重建 `meta` 和每张同名业务表。
- **影响**: 配置名和 SPEC 暗示的保护语义失效，存在误覆盖已有 DB 的风险。
- **建议**: 当目标 DB 已存在且 `IMPORT_OVERWRITE=false` 时立即报错并非零退出。

### Bug #6: 空表识别依赖固定名称 [待修复]

- **现象**: `classifySheet(name)` 只把名称为 `Sheet6` 的表判为空，未依据 `sheet['!ref']`。
- **影响**: 源文件新增其他空白表时会进入月度处理并可能异常；名为 `Sheet6` 的有效表也会被误跳过。
- **建议**: 先按 `!ref` 判断无有效区域，再按严格月份格式或 TOP 映射分类，未识别表应报错或明确跳过。

### 审计缺口 #1: 全量审计脚本缺失 [待修复]

- **现象**: README、TASKS、REVIEWS 均声称 `full_audit.js` 校验 4,441,989 cells，但当前仓库没有该文件。
- **影响**: “零数据丢失”无法从当前交付物复验。
- **当前结论**: 现有 `tests/verify.js` 的 61 项检查通过，只能证明行数、meta 和少量抽样一致，不能替代全量逐 cell 审计。

### 独立复核 #1: 当前 Excel 与 DB 的全量值对比 [通过但未脚本化]

- **范围**: 54 张有效业务表，4,441,989 个源数据单元格。
- **结构问题**: 0。
- **值不一致**: 0（数值按数值等值比较，文本按字符串精确比较，空单元格对应 NULL）。
- **类型变化**: 70,989 个 Excel 数值在 SQLite 中以 TEXT 存储，主要由动态整列类型推断在混合类型列中选择 TEXT 导致。
- **影响**: 数据值未丢失，但依赖 SQLite 原生类型的排序、比较或外部 BI 类型识别可能出现差异；查询时应显式 `CAST`，或后续增加源单元格类型元数据/统一视图。

### Bug #7: `IMPORT_NUMERIC_TOLERANCE` 配置未实现 [已移除无效配置]

- **现象**: `.env.example` 和 SPEC 声明该配置，主转换脚本没有读取。
- **影响**: 用户修改该变量不会产生任何效果。

### Bug #8: `meta.db_size_bytes` 不是最终文件大小 [待修复]

- **现象**: meta 记录 51,113,984 bytes，当前 `market.db` 实际为 52,760,576 bytes。
- **根因**: WAL 模式下在 checkpoint 和关闭连接前读取主 DB 大小。
- **影响**: 不影响业务数据，但 meta 的文件大小字段不准确。

### 数据质量 #10: 2026.04 - 2026.07 市场指标数量级突变 [待业务确认]

- **月销量汇总**: 2026.03 为 291,479；2026.04 为 2,924,738；2026.05 为 5,387,705；2026.06 为 7,583,673；2026.07 为 5,302,834。
- **核验**: 全量逐 cell 对比为 0 value mismatch，确认异常来自源 Excel，不是数据库列错位或转换错误。
- **影响**: 直接纳入 MoM、YoY、年度累计会主导全部趋势，必须先确认统计周期、抓取范围或卖家精灵口径是否改变。

## 自审发现 (2026-08-27) — Round 1: 严重 bug

### Bug #1: TOP 表 header 行错位 [已修复]

- **现象**: 4 张 TOP 表的列名错位为数字 (e.g. `_1, _436710, _13063`)
- **根因**: `processTopSheet` 硬编码 `headerRow = 1`, 但 4 张 TOP 表的 header 实际在 row 0
- **影响**: 4 张 TOP 表共丢失 1 行 / 表, 且列名错误
- **修复**: 将 `headerRow = 1` 改为 `headerRow = 0`
- **验证**: `full_audit.js` 全表 4,441,989 cells 0 mismatch

### Bug #2: TOP销量 (倍率) 空 header 列含数据被丢弃 [已修复]

- **现象**: TOP销量 (倍率) 的 col 18, 20, 22, 24 位置 header 为空, 但数据行在这些列有值
- **根因**: 脚本在 CREATE TABLE 和 INSERT 时都 `if (!headers[i]) continue;` 直接跳过空 header
- **影响**: TOP销量 (倍率) 共 3697 cell 丢失
- **修复**: 空 header 列改为占位名 `_col_<index>`, 保留数据
- **验证**: `full_audit.js` 全表 0 mismatch, TOP销量(倍率) 3697 cell 找回

### Bug #3: tests/verify.js TOP 表 header 检测错误 [已修复]

- **现象**: verify.js 中 `detectHeaderRow` 对 TOP 表返回 1
- **修复**: 改为返回 0 (与 import_xlsx.js 一致)
- **验证**: `verify.js` 全部 PASS, 行数匹配

### Bug #4: tests/verify.js 抽样对比取样范围不一致 [已修复]

- **现象**: Excel 取 "前3+后3", DB 取 "前6", 不一致导致 mismatch
- **修复**: `getDbSample` 改为先取前 3 + 后 3, 与 Excel 对齐
- **验证**: 抽样对比全部 PASS

## 自审发现 (2026-08-27) — Round 2: 源数据质量问题

> 经 `full_audit.js` 全表逐 cell 校验 (4,441,989 cells) 确认 0 mismatch.  
> > 下面记录的是**源数据本身**的不一致性, 属于数据质量问题, 不影响 lossless 保证.

### 数据质量 #1: `上架时间` 列类型不一致 [已知]

- **现象**: 同名列在不同 sheet 类型不同
  - 旧 sheet (202206-202212): Excel `cell.t=s` (字符串 "2020-11-18") -> DB TEXT
  - 新 sheet (202406+): Excel `cell.t=n` (序列号 44105 = 2020-10-19) -> DB INTEGER
- **原因**: Excel 文件早期手动输入 (文本), 后期改为 Excel 日期格式 (序列号)
- **影响**: 跨 sheet 查询需要类型转换 (例如 `WHERE 上架时间 > "2024-01-01" OR CAST(上架时间 AS TEXT) > "2024-01-01"`)
- **当前决策**: 不修改, 保留源数据原貌 (lossless 原则)
- **后续建议**: 可在 SPEC.md 增加可选的 `--normalize-dates` 后处理, 把 Excel 序列号 (30000-50000) 转为 ISO 字符串

### 数据质量 #2: `子体销量` / `子体销售额` 列类型不一致 [已知]

- **现象**: 旧 sheet: TEXT (空值多, 无 INTEGER 样本) -> DB TEXT  
  新 sheet: INTEGER (有真实数据)
- **原因**: 旧 sheet 数据未填充, 类型推断退回 TEXT
- **影响**: 同 #1, 跨 sheet 查询需要类型转换
- **当前决策**: 不修改

### 数据质量 #3: `Coupon` 列类型不一致 [已知]

- **现象**: 旧 sheet: TEXT (空值多) -> DB TEXT  
  新 sheet: REAL (0.4 = 40% 折扣, 22.67 = $22.67 off)
- **原因**: 旧 sheet 无数据, 新 sheet 有不同格式 (百分比 vs 金额)
- **影响**: 同 #1
- **当前决策**: 不修改 (两种格式语义不同, 应由消费者判断)

### 数据质量 #4: `LQS` 列 5 张表为 REAL [已知]

- **现象**: 45 张 INTEGER, 5 张 (2026.3-2026.7) REAL (6.1, 6.4 等小数)

### 数据质量 #5: `月销量增长率` 在 4 张新 sheet 缺失 [已知]
